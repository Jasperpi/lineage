## 1. Genetic maps on GRCh37 (HapMap II / Beagle, Bherer 2017, deCODE 2019)

### Takeaway
Three usable GRCh37 cM maps are downloadable today: the Beagle-hosted PLINK-format HapMap II map (23 MB zip, trivially parsed, the simplest to bundle), the Bhérer 2017 refined sex-specific maps on GitHub (three tarballs, ~24-41 MB each, chr/pos/rate/cM columns), and the IMPUTE2 1000GP Phase 3 bundle (which contains per-chromosome `-m` maps but is a 9.8 GiB download). None of the three carries an explicit open licence on the download itself — all are "cite the paper" academic releases, which is the main legal ambiguity for redistribution.

### Cited Findings
- Beagle's genetic map directory currently lists exactly three files: `plink.GRCh36.map.zip` (29M, 2013-06-08), `plink.GRCh37.map.zip` (23M, 2013-06-08), `plink.GRCh38.map.zip` (45M, 2025-11-03) — [Beagle genetic_maps index, verified 2026-09-25](https://bochet.gcc.biostat.washington.edu/beagle/genetic_maps/)
- `https://bochet.gcc.biostat.washington.edu/beagle/genetic_maps/plink.GRCh37.map.zip` downloads as 23,913,120 bytes and contains `README.txt`, `plink.README.txt` and one `plink.chrN.GRCh37.map` per chromosome; `plink.chr1.GRCh37.map` is 6,228,507 bytes with 256,895 lines — [downloaded and unzipped, verified 2026-09-25](https://bochet.gcc.biostat.washington.edu/beagle/genetic_maps/plink.GRCh37.map.zip)
- PLINK .map line format is 4 whitespace-separated columns `chromosome  marker(.)  cM  bp`; first three lines of chr1 are `1 . 0.000000 55550`, `1 . 0.080572 82571`, `1 . 0.092229 88169` — [file contents, verified 2026-09-25](https://bochet.gcc.biostat.washington.edu/beagle/genetic_maps/plink.GRCh37.map.zip)
- Beagle's own documentation describes these as "human genetic maps — HapMap GrCh36, GrCh37, and GrCh38 genetic maps with cM units in PLINK format", listed as a resource alongside the GPL-licensed Beagle program (`gpl_license  GNU General Public License` covers the software, not the maps) — [Beagle 5.5 page, verified 2026-09-25](https://faculty.washington.edu/browning/beagle/beagle.html)
- The original HapMap II GRCh37 map is still live at NCBI: `https://ftp.ncbi.nlm.nih.gov/hapmap/recombination/2011-01_phaseII_B37/genetic_map_HapMapII_GRCh37.tar.gz`, `Content-Length: 37730100`, `Last-Modified: Wed, 19 Jan 2011 21:21:30 GMT`, `Content-Type: application/x-gzip`, and it serves `Access-Control-Allow-Origin: *` — [HEAD response, verified 2026-09-25](https://ftp.ncbi.nlm.nih.gov/hapmap/recombination/2011-01_phaseII_B37/)
- That tarball's members are `README.txt` and `genetic_map_GRCh37_chrN.txt`; the README states "This folder contains a build GRCh37 genetic map. The map was generated by lifting the HapMap Phase II genetic map from build 35 to GRCh37. The original map was generated using LDhat" — [partial download + tar listing, verified 2026-09-25](https://ftp.ncbi.nlm.nih.gov/hapmap/recombination/2011-01_phaseII_B37/genetic_map_HapMapII_GRCh37.tar.gz)
- Bhérer et al. 2017 maps live in a public GitHub repo containing `Refined_genetic_map_b37.tar.gz` (41,278,300 bytes), `Refined_EUR_genetic_map_b37.tar.gz` (38,730,434 bytes), `Refined_deCODE2014_genetic_map_b37.tar.gz` (24,236,806 bytes) and `interpolate_maps.R`; last commit 2017-04-25 — [git clone of cbherer/Bherer_etal_SexualDimorphismRecombination, verified 2026-09-25](https://github.com/cbherer/Bherer_etal_SexualDimorphismRecombination)
- The Bhérer tarball unpacks to `Refined_genetic_map_b37/{male,female,sexavg}_chrN.txt` with header `chr  pos  rate  cM` (e.g. `chr1  752721  0.00809296  0`) — [tar listing + file head, verified 2026-09-25](https://github.com/cbherer/Bherer_etal_SexualDimorphismRecombination)
- Bhérer README (verbatim): "This folder contains the genetic maps described in Bhérer, C. et al. Refined genetic maps reveal sexual dimorphism in human meiotic recombination at multiple scales. Nat. Commun. 8, 14994 doi:10.1038/ncomms14994 (2017). … The unrefined and refined maps are derived from 3,3 million crossovers from 104,246 meioses. The refined European maps are derived from the 97,723 meioses from individuals European origins. The refined Icelandic map was generated using the data from Kong et al. 2014 (Nature). Note that in this Icelandic map, data is lacking for ~5Mb at each chromosome ends. … Coordinates are in human genome build 37." No licence file is present in the repo — [README.md, verified 2026-09-25](https://raw.githubusercontent.com/cbherer/Bherer_etal_SexualDimorphismRecombination/master/README.md)
- ped-sim documents the canonical recipe for turning the Bhérer maps into a sex-specific simulation map: `wget https://github.com/cbherer/Bherer_etal_SexualDimorphismRecombination/raw/master/Refined_genetic_map_b37.tar.gz` then `printf "#chr\tpos\tmale_cM\tfemale_cM\n" > refined_mf.simmap` and paste the male/female cM columns — [ped-sim README, verified 2026-09-25](https://raw.githubusercontent.com/williamslab/ped-sim/master/README.md)
- The IMPUTE2 1000GP Phase 3 bundle `https://mathgen.stats.ox.ac.uk/impute/1000GP_Phase3.tgz` is still served: `Content-Length: 10473499842` (≈9.75 GiB), `Last-Modified: Mon, 22 Dec 2014 12:47:07 GMT`. Its documentation says it contains "genetic_map* (one file per autosome) — Genetic map file in IMPUTE -m format (physical positions in NCBI b37 coordinates)" plus hap/legend/sample files for 2,504 samples — [HEAD + page text, verified 2026-09-25](https://mathgen.stats.ox.ac.uk/impute/1000GP_Phase3.html)
- deCODE 2019 (Halldórsson et al., *Science* 363:eaau1043) supplementary data files are listed as `aau1043_datas1.gz` (25.01 MB), `datas2.gz` (25.65 MB), `datas3.gz` (25.66 MB), `datas4.gz` (42.70 MB), `datas5.tsv` (10.55 KB), `datas6.xlsx` (2.55 MB), `datas7.tsv` (1.00 MB) — [search result describing the Science supplementary listing](https://www.science.org/doi/10.1126/science.aau1043); a direct HEAD on `https://www.science.org/doi/suppl/10.1126/science.aau1043/suppl_file/aau1043_datas3.gz` returned **HTTP 403** from this session **[not verified]**
- The Bhérer repo also redistributes a deCODE-2014-derived refined map (`Refined_deCODE2014_genetic_map_b37.tar.gz`), i.e. an older deCODE pedigree map in build 37, which is a practical GRCh37 substitute for the 2019 deCODE map (which is published in GRCh38) — [repo contents, verified 2026-09-25](https://github.com/cbherer/Bherer_etal_SexualDimorphismRecombination)

### Inferences
- For Lineage's cM needs (segment lengths, IBD reporting) the Beagle PLINK GRCh37 map is the cheapest to bundle: ~3.3 M lines total, but after thinning to the ~600-700k consumer-chip positions and storing as a delta-encoded binary or a chromosome-wise `Float32Array`, a bundled map is on the order of a few MB, and interpolation between map points is a two-line linear interpolation.
- Because the maps are academic releases with no SPDX licence, the defensible position is: derive and ship interpolated cM values (a transformation of published aggregate map data), attribute the source paper and version in the app and in the data provenance file, and record the download URL and date. This is what ped-sim, Beagle and most tools do in practice — but it is a norm, not a written permission.
- deCODE 2019 is GRCh38-native and paywalled-adjacent; Bhérer 2017 (build 37, sex-specific, GitHub-hosted) is the better fit for a GRCh37 consumer-genotype app that wants sex-specific maps.

### Gaps
- No explicit licence text exists for any of the three maps. I found no LICENSE file in the Bhérer repo, no terms statement on the Beagle genetic-maps index, and no licence in the HapMap recombination directory — redistribution permission is therefore **unclear** rather than granted.
- I could not fetch the deCODE 2019 supplementary files (403 from science.org through this session's proxy), so their exact formats, column headers and current URLs are unverified.
- I did not check whether the HapMap "Data Release Policy" page (hapmap.ncbi.nlm.nih.gov) still resolves; the recombination sub-directory itself carries no policy file.

## 2. 1000 Genomes phase 3: populations, coordinates, reuse policy, Ensembl/gnomAD population names

### Takeaway
IGSR's beta API returns all 26 phase-3 populations with latitude/longitude and sample counts in one POST, and Ensembl REST returns per-population frequencies under exactly the `1000GENOMES:phase_3:XXX` names Lineage already uses. ### Inferences
- Lineage can bundle a 26-population × N-SNP frequency table derived from the phase-3 sites VCF (or from Ensembl) and ship it: the data are aggregate, embargo-free, and the only real obligation is the Nature 2015 citation. Storing 700k SNPs × 26 populations as uint16 fixed-point (freq×10000) is ~36 MB raw, ~10-15 MB gzipped — plausible as a lazily-fetched, versioned asset rather than an initial-load bundle.
- Because the **GRCh37 REST mirror lacks gnomAD frequencies**, any plan that wants gnomAD's finer groups (`ami`, `asj`, `mid`, `fin`) via Ensembl must use the GRCh38 endpoint and therefore needs rsID-based lookup (Lineage's files are GRCh37 by position but carry rsIDs, so rsID lookup sidesteps liftover).
- The IGSR counts vs Ensembl counts mismatch is a real trap for a UI: show Ensembl's phase-3 counts next to phase-3 frequencies, and use IGSR only for the map coordinates.

### Gaps
- The `#g1k_data_reuse` anchor on internationalgenome.org/about did not render any dedicated "data reuse" prose when fetched (the anchor exists, the section text did not appear in the fetched HTML), so I could not quote the canonical phase-3 reuse statement verbatim; the IGSR Disclaimer text above is the closest authoritative wording I could verify.
- The IGSR TSV export endpoint (`/api/beta/population/_search/igsr_populations.tsv.tsv`) returned `{"detail":"Method Not Allowed"}` on GET — only the POST JSON search worked.

## 3. HGDP (Bergström 2020) and SGDP (Mallick 2016) — coordinates, access, licences, precomputed frequencies

### Takeaway
HGDP is the strongest candidate for a "finer populations" map layer: a 107 KB metadata file gives per-sample population, region, latitude and longitude for all 929 samples across 54 populations, and the access README grants unusually clear freedom ("freely available with no restrictions"). Per-population allele frequencies are **not** published as a small precomputed file anywhere I could verify — the gnomAD HGDP+1KG VCFs do carry per-population `AF_*` fields but are hundreds of GB per chromosome, and the Geography of Genetic Variants API returned 500 errors today.

### Cited Findings
- HGDP metadata: `https://ngs.sanger.ac.uk/production/hgdp/hgdp_wgs.20190516/metadata/hgdp_wgs.20190516.metadata.txt` (listed as 107K, 930 lines = 929 samples + header) with columns `sample, library, sample_accession, source, library_type, population, latitude, longitude, region, sex, coverage, freemix, capmq, insert_size_average, array_non_reference_discordance, library_alias_ENA` — [downloaded, verified 2026-09-25](https://ngs.sanger.ac.uk/production/hgdp/hgdp_wgs.20190516/metadata/hgdp_wgs.20190516.metadata.txt)
- Parsed: **929 samples, 54 populations, 7 regions** (AFRICA, AMERICA, CENTRAL_SOUTH_ASIA, EAST_ASIA, EUROPE, MIDDLE_EAST, OCEANIA), each population carrying one lat/lon pair, e.g. Brahui 30.5/66.5 (n=25), Mbuti 1/29 (n=13), French 46/2 (n=28), Sardinian 40/9 (n=28), Karitiana -10/-63 (n=12), PapuanHighlands -6.1/145.4 (n=9), San -21/20 (n=6), Yakut 63/129.5 (n=25) — [own parse of the metadata file, verified 2026-09-25](https://ngs.sanger.ac.uk/production/hgdp/hgdp_wgs.20190516/metadata/hgdp_wgs.20190516.metadata.txt)

### Inferences
- The practical route to HGDP per-population frequencies for a ~700k-SNP panel is not to download 295 GB VCFs but to stream the gnomAD HGDP+1KG VCFs with an index and extract only the panel positions (the `.tbi` files are ~40-265 KB, so random access is cheap), pulling the `AF_<population>` INFO fields directly. That is a one-time offline build step producing a compact bundled table.
- HGDP's licence wording ("freely available with no restrictions on the types of analyses") plus a citation request is the most redistribution-friendly of all the population datasets here; combined with the per-population lat/lon it is the natural basis for a world map with 54 points.
- GGV's API being down means it should not be a runtime dependency; its value is as a design precedent (and the gnomAD `hgdp_tgp_ggv_intersect.mt` shows the intersection has already been computed once).

### Gaps
- No precomputed, small, per-population HGDP allele-frequency file (e.g. a PLINK `.frq.strat` or a TSV) could be found at an official URL; the only verified sources are the giant VCFs.
- gnomAD's own terms page could not be read verbatim (JS-rendered); the "MIT" label comes from the AWS registry entry, not from Broad's own page, so the exact licence wording for gnomAD aggregates is **unverified**.
- SGDP per-population allele frequencies: not found precomputed anywhere; the SGDP page offers PLINK datasets and VCFs but I did not verify a frequency file.

### Inferences
- SNP overlap with consumer chips: the HO panel (584,131 sites, Affymetrix Human Origins) and the 1240k panel (1,233,013 sites) are both hg19 and both were chosen from ascertainment panels heavily overlapping common variation, so a consumer 600-700k GSA file will intersect them substantially — but the exact intersection must be computed from the `.snp` files (77 MB for 1240k, 37 MB for HO) against a chip manifest. I did **not** compute this intersection, so no number should be quoted.
- Bundling the `.anno` (13-15 MB, or ~2-3 MB after stripping to ID/date/lat/lon/group/Y/mt and gzipping) gives Lineage an ancient-sample map layer with dates and haplogroups **without redistributing any genotypes at all** — and CC0 removes all licence friction for the annotations.
- For actual ancient-ancestry estimation the genotype files are 1.9-12.4 GB; a browser app would need a precomputed, offline-derived allele-frequency table per ancient group (e.g. the ~50-200 best-covered Group IDs × panel SNPs), which is exactly the kind of aggregate CC0 permits redistributing.

### Gaps
- I did not download the `.snp` or `.geno` files, so I cannot state the measured AADR × GSA overlap, nor verify the tgeno binary layout first-hand (the README describes it).
- The README's "Table: overlap between panel sets" is an embedded image/table in the .docx that did not extract as text, so exact pairwise panel overlaps are unverified.

## 5. Haplogroup trees (mtDNA and Y)

### Takeaway
For mtDNA, the cleanest bundleable asset is the Haplogrep 3 tree ecosystem: `genepi/phylotree-rcrs-17` is **MIT-licensed** and ships PhyloTree 17 as `tree.xml` plus weights and nomenclature rules, while PhyloTree's own Build 17 download is a single 14.5 MB HTML file with a citation requirement and no licence. For Y, **YFull's YTree is on GitHub under CC BY 4.0** — a 15.4 MB JSON with ~69,676 nodes — which is the only large, openly licensed Y tree I could verify. FTDNA's Mitotree is available but **CC BY-NC-ND 4.0 (non-commercial, no derivatives)**, which rules out derived compact formats.

### Cited Findings
- PhyloTree homepage citation requirement (verbatim): "Please cite the mtDNA tree as follows: van Oven M, Kayser M. 2009. Updated comprehensive phylogenetic tree of global human mitochondrial DNA variation. Hum Mutat 30(2):E386-E394. http://www.phylotree.org. doi:10.1002/humu.20921"; the site describes "a comprehensive phylogenetic tree of worldwide human mitochondrial DNA variation, currently comprising over 5,400 nodes (haplogroups) with their defining mutations" and "Database of 24,275 entire mtDNA sequences considered for tree construction" — [phylotree.org, verified 2026-09-25](https://www.phylotree.org/)
- The current build is **mtDNA tree Build 17 (18 Feb 2016)**; the whole-tree download is `https://www.phylotree.org/builds/mtDNA_tree_Build_17.zip` = **421,842 bytes**, containing a single file `mtDNA tree Build 17.htm` of **14,482,768 bytes** — i.e. the tree is distributed as an HTML table, not a structured format — [downloaded and unzipped, verified 2026-09-25](https://www.phylotree.org/tree/index.htm)
- No licence statement appears on phylotree.org's tree pages; only the citation request above. (`https://www.phylotree.org/resources/` returned 403.) — [verified 2026-09-25](https://www.phylotree.org/tree/index.htm)
- Haplogrep 3 (the maintained mtDNA classifier) is **MIT licensed** (`LICENSE` = "MIT License"), last commit 2026-06-09, and is "tree-independent", installing trees as separate versioned repos — [git clone of genepi/haplogrep3, verified 2026-09-25](https://github.com/genepi/haplogrep3)

- **YFull YTree is public on GitHub**: `YFullTeam/YTree` (last commit 2026-09-22) contains `current_tree.json` (**15,408,762 bytes**), `current_version.txt` (**14.06.0**), and an archive of per-version trees (`ytree/tree_8.04.1.json` … `ytree/tree_14.06.0.zip`). Parsing `current_tree.json` gives **69,676 nodes**; each node has fields `id` (haplogroup name, e.g. `A00*`), `snps` (comma-separated equivalent SNP names), `formed`, `tmrca`, `formedlowage/highage`, `tmrcalowage/highage`, `children` — [git clone + parse, verified 2026-09-25](https://github.com/YFullTeam/YTree)
- YTree's `LICENSE.md` is the full text of the **Creative Commons Attribution 4.0 International Public License** — [verified 2026-09-25](https://github.com/YFullTeam/YTree/blob/master/LICENSE.md)
- YTree README (verbatim excerpt): "YTree https://www.yfull.com/tree/ is a tree of the company YFull was created in the 2013 year based on the tree ISOGG https://isogg.org/tree/ of the mutations on the Y chromosome… Every month YTree is updated. As of May 2020, there are more than 15000 subclades. Almost, for each subclade was calculated the age estimation based on the downstream mutations." — [verified 2026-09-25](https://github.com/YFullTeam/YTree)
- AADR itself calls Y haplogroups "automatically called based on Y-full 12.03" in both terminal-mutation and ISOGG notation — so YFull naming is already the de-facto standard in ancient-DNA annotation — [AADR anno header, verified 2026-09-25](https://dataverse.harvard.edu/api/access/datafile/13994515)
- ISOGG: `https://isogg.org/tree/` is behind a Cloudflare interstitial ("Just a moment… Enable JavaScript and cookies to continue") and `ISOGG_YDNA_Version_History.html` returned **HTTP 403** to automated fetches — [verified blocked 2026-09-25](https://isogg.org/tree/). Search results state the final ISOGG tree version was **15.73, dated 11 July 2020** — [search result citing ISOGG version history](https://isogg.org/tree/ISOGG_YDNA_Version_History.html) **[not verified directly]**

### Inferences
- A browser app can bundle a compact Y tree derived from YTree under CC BY 4.0 with attribution ("YFull YTree v14.06.0, CC BY 4.0") — the 15.4 MB JSON reduces dramatically if only branch names + defining SNP lists for branches reachable by consumer-chip Y SNPs are kept.
- For mtDNA, deriving a compact JSON from `genepi/phylotree-rcrs-17`'s `tree.xml` (MIT) is legally the cleanest path; scraping PhyloTree's own 14.5 MB HTML gives the same content but with only a citation request and no licence, and the FTDNA Mitotree's ND clause forbids the reformatting a bundled app needs.
- Consumer chips genotype only a few thousand Y SNPs and a few thousand mtDNA positions, so branch resolution will be coarse regardless of tree size; the tree's value is in naming and in ancestry-informative structure, not in depth.

### Gaps
- **Haplogroup geographic frequency datasets**: I found no open, citable dataset of haplogroup frequencies by population. FTDNA's Mitotree ships `myorigins.frequencies.txt.gz` (an FTDNA-derived frequency annotation) but under CC BY-NC-ND. YFull publishes sample geography on its website, not as a licensed dataset. This is a genuine hole.
- ISOGG's tree format, licence and download files are unverified because the site blocks automated access; only search-result claims about version 15.73 (July 2020) are available.
- FamilyTreeDNA's public Y haplotree (discover.familytreedna.com) is a client-rendered app; my fetch returned no readable content, so its terms and any download/API are **unverified**.

## 6. HIrisPlex-S pigmentation model

### Takeaway
The 41-SNP marker panel is openly published and reproduced in an MIT-licensed R package, and **28 of the 41 SNPs are on the Illumina GSA v3 chip** (measured against the real manifest). But the multinomial logistic regression coefficients themselves live in the supplementary tables of three Erasmus MC papers and in the closed web tool — I found **no open-source implementation that embeds the coefficients**; both open tools I examined either only build the upload CSV or explicitly instruct the user to upload to hirisplex.erasmusmc.nl.

### Cited Findings
- The 41 HIrisPlex-S SNPs in canonical order, with the required input allele, as packaged in the MIT-licensed `hirisplexr` R package (`inst/extdata/hirisplex_panels.csv`, "Panel definitions (rsID and required input allele) are packaged and sourced from the official webtool and manual"): rs312262906(A), rs11547464(A), rs885479(T), rs1805008(T), rs1805005(T), rs1805006(A), rs1805007(T), rs1805009(C), rs201326893(A), rs2228479(A), rs1110400(C), rs28777(C), rs16891982(C), rs12821256(G), rs4959270(A), rs12203592(T), rs1042602(T), rs1800407(A), rs2402130(G), rs12913832(T), rs2378249(C), rs12896399(T), rs1393350(T), rs683(G), rs3114908(T), rs1800414(C), rs10756819(G), rs2238289(C), rs17128291(C), rs6497292(C), rs1129038(G), rs1667394(C), rs1126809(A), rs1470608(A), rs1426654(G), rs6119471(C), rs1545397(T), rs6059655(T), rs12441727(A), rs3212355(A), rs8051733(C) — [git clone of adhikari-statgen-lab/hirisplexr, MIT, verified 2026-09-25](https://github.com/adhikari-statgen-lab/hirisplexr)
- Model structure (three nested models): "the previously developed IrisPlex model for eye colour prediction based on 6 SNPs, the previous HIrisPlex model for hair colour prediction based on 22 SNPs, and the recently introduced HIrisPlex-S model for skin colour prediction based on 36 SNPs"; the assay is "two SNaPshot-based multiplex assays targeting a total of 41 SNPs via a novel multiplex assay for 17 skin colour predictive SNPs and the previous HIrisPlex assay for 24 eye and hair colour predictive SNPs, 19 of which also contribute to skin colour prediction" — [Chaitanya et al. 2018, HIrisPlex-S, FSI:Genetics (open-access author copy)](https://scholarworks.indianapolis.iu.edu/bitstreams/ec6ac6ff-811b-4adb-9c8c-130499201b0f/download)
- Coefficient provenance: the three papers that carry the published coefficient tables are Walsh et al. 2011 (IrisPlex, 6 SNPs, eye), Walsh et al. 2013 (HIrisPlex, 22 SNPs, hair), Chaitanya et al. 2018 (HIrisPlex-S, 36 SNPs, skin) — [Chaitanya et al. 2018](https://www.sciencedirect.com/science/article/abs/pii/S1872497318302205)
- `aHISplex` (GPL-3, Maróti et al., last commit 2026-02-10) is a full ancient-DNA pipeline for the 41 markers, but its documented workflow is: "1. Run aHISplex.sh 2. **Upload the output of step 1 (HISplex41_upload.csv) to https://hirisplex.erasmusmc.nl/ web service.** Download/save the resulting phenotype probability output file. 3. Use classifHISplex to evaluate phenotype probabilities applying the rules described in the HIrisPlex-s user manual." — i.e. it does not implement the model itself — [git clone of zmaroti/aHISplex, verified 2026-09-25](https://github.com/zmaroti/aHISplex)
- `hirisplexr` likewise only "builds HIrisPlex/HIrisPlex-S CSV files from PLINK data" for upload — [README, verified 2026-09-25](https://github.com/adhikari-statgen-lab/hirisplexr)
- aHISplex bundles GRCh37/hg19/GRCh38 reference panels for 11 genomic regions harbouring the 41 markers (`aHISplex_data/ref_GRCh37/GRCh37_15_25687817_31030163.bin` etc.), confirming the markers cluster in 11 loci — useful if Lineage ever wants local imputation — [repo file list, verified 2026-09-25](https://github.com/zmaroti/aHISplex)
- **Chip coverage measured**: of the 41 HIrisPlex-S rsIDs, **28 are present on the Illumina GSA v3 manifest** and 13 are absent: rs312262906, rs885479, rs28777, rs3114908, rs10756819, rs2238289, rs17128291, rs6497292, rs6119471, rs1545397, rs12441727, rs3212355, rs8051733 — [own analysis of `GSA-24v3-0_A2.csv`, verified 2026-09-25](https://support.illumina.com/downloads/infinium-global-screening-array-v3-0-product-files.html)

### Inferences
- A browser implementation can legally ship the SNP panel and the allele-encoding rules (facts, and reproduced under MIT in hirisplexr), but shipping the regression coefficients means copying tables from journal supplementary files whose licences vary by publisher — that needs a per-paper check before bundling.
- With 28/41 SNPs on GSA, a consumer-file prediction is necessarily partial. The HIrisPlex-S tool accepts missing markers (the model degrades rather than fails), but eye colour is the safest output because its 6 IrisPlex SNPs — notably rs12913832, rs1800407, rs12896399, rs16891982, rs1393350, rs12203592 — are all in the 28 present on GSA.
- The absence of any open implementation with embedded coefficients is itself a finding: it suggests either licence caution or the authors' preference for the central web tool, and it means Lineage would be doing something novel (and should be careful about claiming forensic-grade accuracy).

### Gaps
- I did not obtain the actual coefficient values or their exact supplementary-table identifiers (e.g. "Table S3 of Chaitanya 2018"), because the publisher pages are paywalled to this session; the open-access author copy at IUPUI ScholarWorks was found via search but not fetched in full.
- Whether the coefficient tables may be redistributed (CC-BY supplementary vs Elsevier all-rights-reserved) is unresolved.

## 7. Consumer chip content (Illumina GSA manifests, which tests use GSA)

### Takeaway
The GSA v3.0 manifest is a public, unauthenticated download (~70 MB zip, 284 MB CSV, 654,027 loci, 627,982 unique rsIDs) and is the right basis for choosing a panel that exists on most modern consumer files. Which vendors use GSA is less crisp: sources agree 23andMe v5 and Living DNA are GSA-based, but disagree about MyHeritage and FTDNA.

### Cited Findings
- GSA v3.0 product files page lists: Cluster File ZIP (40 MB), LIMS Product Descriptor ZIP (<1 MB), "Manifest File (BPM Format – GRCh37)" ZIP (26 MB), "Manifest File (BPM Format - GRCh38)" ZIP (93 MB), "Manifest File (CSV Format – GRCh37)" ZIP (67 MB), "Manifest File (CSV Format - GRCh38)" ZIP (67 MB), all dated **Aug 12, 2019** — [Illumina support page, verified 2026-09-25](https://support.illumina.com/downloads/infinium-global-screening-array-v3-0-product-files.html)
- The direct download URLs are unauthenticated: `https://support.illumina.com/content/dam/illumina-support/documents/downloads/productfiles/global-screening-array-24/v3-0/GSA-24v3-0-A1-manifest-file-csv.zip` and `…/GSA-24v3-0-A2-manifest-file-csv.zip` (plus `-A1/-A2-manifest-file-bpm.zip`, `GSA-24v3-0-A1-cluster-file.zip`) — [page link extraction, verified 2026-09-25](https://support.illumina.com/downloads/infinium-global-screening-array-v3-0-product-files.html)
- I downloaded the A2 CSV manifest: **70,119,981 bytes** zipped, containing one member `GSA-24v3-0_A2.csv` of **284,225,383 bytes**. Its header block reads `Illumina, Inc. / [Heading] / Descriptor File Name,GSA-24v3-0_A2.bpm / Assay Format,Infinium HTS / Date Manufactured,8/7/2019 / Loci Count ,654027`, and the assay rows carry `IlmnID,Name,IlmnStrand,SNP,AddressA_ID,AlleleA_ProbeSeq,AddressB_ID,AlleleB_ProbeSeq,GenomeBuild,Chr,MapInfo,Ploidy,Species,Source,SourceVersion,SourceStrand,…` with `GenomeBuild` = 38 — so **A2 is the GRCh38 manifest and A1 is the GRCh37 one** — [downloaded and parsed, verified 2026-09-25](https://support.illumina.com/content/dam/illumina-support/documents/downloads/productfiles/global-screening-array-24/v3-0/GSA-24v3-0-A2-manifest-file-csv.zip)
- Parsed counts: **654,050 assay rows, 654,035 unique marker names, 627,982 unique rsIDs** on GSA v3 — [own parse, verified 2026-09-25](https://support.illumina.com/content/dam/illumina-support/documents/downloads/productfiles/global-screening-array-24/v3-0/GSA-24v3-0-A2-manifest-file-csv.zip)
- The GSA v3.0 **support** files page additionally offers, as separate zips: `…-a1-b151-rsids.zip` (rsID mapping), `…-a1-bed.zip`, `…-a1-physical-genetic-coordinates.zip` (physical↔genetic coordinates — directly relevant to cM work), `…-a1-population-reports-maf-copy-numbers.zip` (population MAF reports), `…-a1-strand-report.zip`, `…-a1-annotated.zip`, and legacy-overlap comparisons against v2.0 — [Illumina support files page, verified 2026-09-25](https://support.illumina.com/downloads/infinium-global-screening-array-v3-0-support-files.html)
- A GSA **v4.0** product line exists; its support page links `GSA-48v4-0_D2_b155_rsids.txt` and demo data — [Illumina GSA v4.0 support files, verified 2026-09-25](https://support.illumina.com/downloads/global-screening-array-support-files.html)
- Vendor chips: "23andMe v5, LivingDNA v1, FTDNA v2, and MyHeritage v2 use the core Illumina Global Screen Array (GSA) chip with the addition of different custom SNPs" — [GenomePrep survey of DTC genotype data, PMC8267563](https://pmc.ncbi.nlm.nih.gov/articles/PMC8267563/); **contradicted by** a summary stating "AncestryDNA, FamilyTree DNA and My Heritage have mostly retained their choice with the Illumina OmniExpress chip" — [ISOGG wiki autosomal SNP comparison chart, via search](https://isogg.org/wiki/Autosomal_SNP_comparison_chart)
- Reported marker counts per vendor: AncestryDNA v2 ≈664,000; MyHeritage v2 ≈720,000; 23andMe v5 ≈640,000; FamilyTreeDNA ≈702,000 — [search summary of the ISOGG autosomal SNP comparison chart](https://isogg.org/wiki/Autosomal_SNP_comparison_chart) **[not verified directly — ISOGG blocks automated fetches]**

### Inferences
- 627,982 unique rsIDs on GSA v3 matches the "≈640k SNPs" figure quoted for 23andMe v5, which is consistent with GSA-core + custom content and supports using the GSA manifest as the intersection base for a bundled panel.
- A robust panel design is: take the intersection of GSA v3 rsIDs with the AADR HO/1240k `.snp` sets and with the phase-3 sites VCF, then keep only markers with non-trivial MAF in at least one super-population. That intersection is computable entirely offline from files verified above.
- Illumina's manifests carry no open licence statement on the download pages; treating rsID lists derived from them as facts (rather than redistributing the manifest) is the safer posture.

### Gaps
- Illumina's terms for redistributing manifest-derived content were not located on the download pages; **unclear**.
- The vendor-chip question could not be settled from primary sources this session (the ISOGG wiki, the usual reference, blocks automated access; the GenomePrep paper is from 2021 and may not reflect 2026 chip versions). Treat "which tests use GSA in 2026" as unresolved.

## 8. World geography base maps (Natural Earth / world-atlas TopoJSON)

### Takeaway
Fully settled and trivially bundleable: Natural Earth is public domain with no attribution required, and the `world-atlas` TopoJSON redistribution is ISC-licensed with files from 55 KB to 3.7 MB — the 110m countries file at 107,761 bytes is ideal for a browser world map of population points.

### Cited Findings
- Natural Earth Terms of Use (verbatim): "All versions of Natural Earth raster + vector map data found on this website are in the public domain. You may use the maps in any manner, including modifying the content and design, electronic dissemination, and offset printing. The primary authors, Tom Patterson and Nathaniel Vaughn Kelso, and all other contributors renounce all financial claim to the maps and invites you to use them for personal, educational, and commercial purposes. No permission is needed to use Natural Earth. Crediting the authors is unnecessary. However, if you wish to cite the map data, simply use one of the following. Short text: Made with Natural Earth. Long text: Made with Natural Earth. Free vector and raster map data @ naturalearthdata.com." — [Natural Earth Terms of Use, verified 2026-09-25](https://www.naturalearthdata.com/about/terms-of-use/)
- `world-atlas` is "a convenient redistribution of Natural Earth's vector data, **version 4.1.0**, as TopoJSON"; files are quantized, unprojected, in spherical coordinates/decimal degrees; each country carries `id` = ISO 3166-1 numeric and `properties.name` — [world-atlas README, verified 2026-09-25](https://github.com/topojson/world-atlas)
- Licence: the npm package metadata gives `"name": "world-atlas", "version": "2.0.2", "license": "ISC", "author": Mike Bostock` (there is no LICENSE.md in the repo — that path 404s) — [package.json on the CDN, verified 2026-09-25](https://cdn.jsdelivr.net/npm/world-atlas@2/package.json)
- Verified file sizes from `https://cdn.jsdelivr.net/npm/world-atlas@2/…`: `countries-110m.json` 107,761 B; `countries-50m.json` 756,420 B; `countries-10m.json` 3,661,071 B; `land-110m.json` 55,207 B; `land-50m.json` 545,534 B. The CDN serves `access-control-allow-origin: *` and `cache-control: public, max-age=604800` — [downloaded, verified 2026-09-25](https://cdn.jsdelivr.net/npm/world-atlas@2/countries-110m.json)

### Inferences
- Bundling `countries-110m.json` (105 KB, ~35 KB gzipped) plus a small JSON of population coordinates (26 × 1KG + 54 × HGDP + AADR ancient sites) gives a complete offline world-map layer with no licence obligations beyond an optional "Made with Natural Earth" credit.
- Since Natural Earth requires no attribution and world-atlas is ISC, this is the only dataset in this report with zero legal friction — worth noting in Lineage's provenance file as the baseline example of what good terms look like.

### Gaps
- None material. (The repository has no LICENSE file, so the ISC declaration comes from package metadata rather than a licence text in the repo — a minor formality.)

## Cross-cutting notes for Lineage

### Takeaway
Only two of the eight dataset families carry a machine-readable open licence (AADR = CC0 1.0; YFull YTree = CC BY 4.0; plus Natural Earth public domain and world-atlas ISC for geography). Everything else is "freely downloadable with a citation request" or silent — which is workable for redistributing *aggregates*, but must be documented per-source.

### Cited Findings
- Licence summary of what was verified this session: AADR **CC0 1.0** ([Dataverse](https://dataverse.harvard.edu/api/datasets/:persistentId/?persistentId=doi:10.7910/DVN/FFIDCW)); YFull YTree **CC BY 4.0** ([LICENSE.md](https://github.com/YFullTeam/YTree)); Haplogrep 3 + phylotree-rcrs-17 + phylotree-fu-rcrs **MIT** ([repos](https://github.com/genepi/phylotree-rcrs-17)); hirisplexr **MIT**, aHISplex **GPL-3** ([repos](https://github.com/adhikari-statgen-lab/hirisplexr)); FTDNA Mitotree **CC BY-NC-ND 4.0** ([repo](https://github.com/genebygene/mitotree)); Natural Earth **public domain** ([terms](https://www.naturalearthdata.com/about/terms-of-use/)); world-atlas **ISC** ([package.json](https://cdn.jsdelivr.net/npm/world-atlas@2/package.json)); gnomAD listed as **MIT** on AWS Open Data ([registry](https://registry.opendata.aws/broad-gnomad/)); HGDP "freely available with no restrictions" + cite Bergström 2020 ([README](https://ngs.sanger.ac.uk/production/hgdp/hgdp_wgs.20190516/README.data-access.hgdp_wgs.20190516.txt)); 1000G "available without embargo… cite in the usual way" ([IGSR disclaimer](https://www.internationalgenome.org/IGSR_disclaimer)); genetic maps (HapMap/Beagle, Bhérer, deCODE) **no licence found**.
- Lineage's current code path uses `/variation/homo_sapiens/{rsid}?pops=1` (single) and a POST batch form, and filters population names with the regex `^1000GENOMES:phase_3:(AFR|AMR|EAS|EUR|SAS)$` — [`/home/user/jaspermeller/lineage/packages/fetch/src/ensembl.ts`](file:///home/user/jaspermeller/lineage/packages/fetch/src/ensembl.ts) lines 70, 78, 93 (read this session)
- The repo's synthetic sample files (`/home/user/jaspermeller/lineage/data/samples/tester.txt`, 6,068 lines, header "SYNTHETIC sample generated by Lineage… Layout follows the 23andMe raw data format on build 37") are too small to measure real chip overlap — only 9 of the 41 HIrisPlex-S SNPs appear in them (read this session).

### Inferences
- Switching that regex from the five super-populations to all 26 `1000GENOMES:phase_3:*` codes is a one-line change that immediately unlocks the finer-population map, since the API already returns all 26 in the same response.
- A `provenance.json` alongside each bundled asset — source URL, fetch date, upstream version string (AADR "V14 (v66.p1)", YTree "14.06.0", Ensembl "release 116", GSA "GSA-24v3-0_A2, Loci Count 654027", world-atlas "2.0.2 / Natural Earth 4.1.0"), licence and required citation — would satisfy every citation request found above and make the "versioned reference data" goal auditable.

### Gaps
- Nothing here establishes whether redistributing *derived aggregates* from the unlicensed genetic maps is permitted; that remains the single clearest legal risk of the bundling plan.
